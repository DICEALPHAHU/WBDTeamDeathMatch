# 排位段位

段位数据存在 `plugins/WBDTeamDeathmatch/ranked.db`（SQLite），全部配置在 `season.yml`。

只有**没有**在 `arenas.yml` 里标 `unrank: true` 的场地才结算段位。

---

## 段位表

| 段位 | RP 区间 | 小段 | 入场费 |
|---|---|---|---|
| 菜鸟 | 0 – 999 | IV / III / II / I | **0** |
| 青铜 | 1000 – 1999 | IV / III / II / I | **0** |
| 白银 | 2000 – 2999 | IV / III / II / I | 12 |
| 黄金 | 3000 – 3999 | IV / III / II / I | 24 |
| 铂金 | 4000 – 4999 | IV / III / II / I | 36 |
| 钻石 | 5000 – 5999 | IV / III / II / I | 48 |
| 大师 | 6000 – 7499 | IV / III / II / I | 60 |
| 猎杀 | 7500+ | 无（按分数排名） | 75 |

小段每 250 分一档（大师是每 375 分），序号**从低到高**排：`IV` 最低、`I` 最高。所以 RP 越高罗马数字越小——这不是 bug，是段位系统的惯例。

菜鸟与青铜入场费为 0 是刻意的：新手期扣分会让新人直接弃坑。猎杀段无上限也无小段，它就是"顶部分段"。

## 计分公式

```
RP变化 = 名次分(胜负) + 比分差修正 + 击杀分 + 队内排名分 − 入场费
```

| 项 | 默认值 |
|---|---|
| 名次分 · 赢 / 平 / 输 | `+120` / `+30` / `−60` |
| 比分差修正 | `round((我方比分 − 对方比分) / 目标击杀数 × 25)`，夹在 ±25 |
| 击杀分 | 每杀 `+6`，**封顶 10 杀**（最多 +60） |
| 队内排名（按击杀） | 第 1 `+15` / 第 2 `+8` / 第 3 `+3` |
| 入场费 | 见上表 |

### 黄金段（入场费 24）的典型局

| 情况 | 算式 | 净变化 |
|---|---|---|
| 赢 50:20 · 12 杀 · 队内第 1 | +120 +15 +60 +15 −24 | **+186** |
| 赢 50:45 · 3 杀 · 队内第 4 | +120 +3 +18 +0 −24 | **+117** |
| 输 20:50 · 12 杀 · 队内第 1 | −60 −15 +60 +15 −24 | **−24** |
| 输 45:50 · 5 杀 · 队内第 2 | −60 −3 +30 +8 −24 | **−49** |
| 平 30:30 · 8 杀 · 队内第 1 | +30 +0 +48 +15 −24 | **+69** |

### 为什么要加"比分差"和"队内排名"

Apex 一局有 20 队，名次是 1~20 的**连续量**，所以"第 3 名"和"第 17 名"能拉开差距。死斗只有两队，名次是**二元的**——直接套用会退化成"赢 +120、输 −60"，个人表现完全不影响分数，玩十局之后大家的分只跟着胜率走。

比分差修正让"50:20 碾压"和"50:45 险胜"不同，队内排名让 carry 和躺赢不同。

### 为什么击杀分必须封顶

Apex 里杀人与名次相关性弱，所以 KP 上限设得高一些也没关系。而**死斗里击杀就是胜负的成因**，两者高度共线——不封顶等于把同一件事算两遍，纯刷人头的收益会盖过团队胜负，段位就退化成击杀排行榜了。

### 为什么输队打得再好也上不了分

看上面第 3 行：输了但 12 杀、队内第 1，净变化仍然是 **−24**。这是刻意的——如果输队刷人头也能涨分，那"赢了但队友全在送"的局就没有意义了。

## 中途加入

比赛**已开打之后**才加入的玩家（`/tdm join` 时状态为 `LIVE`），结算时：

- 只给**击杀分**
- 不给名次分、不给队内排名分
- **不扣入场费**

理由是名次分度量的是"整场表现"。给中途加入者算名次分，等于奖励"专挑赢面大的局进去蹭分"。而击杀分是他实打实打出来的，照给。

这类玩家在战报里会显示"中途加入"而不是空白，免得被当成漏算了。

---

## 中途离开

**比赛中途（`LIVE` 阶段）离开**：

```
RP变化 = −(2 × 入场费)     本局不结算名次分 / 击杀分 / 队内排名分
```

三种行为的边界：

| 行为 | 是否受罚 | 原因 |
|---|---|---|
| 比赛中途 `/tdm leave` | ✅ | 主动退出 |
| 比赛中途掉线 | ✅ | 否则拔网线就成了逃避败场的标准操作 |
| 等待阶段 / 结算阶段离开 | ❌ | 那时候走人没有任何可逃避的东西 |
| 关服、强制停赛、场地重建导致的清场 | ❌ | 那不是玩家的选择——不豁免的话一次关服就会罚掉全场人 |

离开时还会记一场**负**战绩。不记的话，一个总在劣势时退出的玩家会拥有一个漂亮的胜率，而那个数字是假的。

> **已知代价**：扣"双倍入场费"这条规则本身决定了**菜鸟与青铜（入场费 0）退出没有分数惩罚**。考虑到这两个段位本来就有保护，这个结果可以接受；如果希望这两个段位也疼，需要一个额外的固定惩罚值。

## 段位保护

两层：

**1. 菜鸟段锁死。** RP 永不为负（`protection.floor-rp: 0`）。新手连输几局看着自己的分数变成负数，基本就弃坑了。

**2. 升段保护。** 每次升到新段位后的 `demotion-shield-matches`（默认 3）场之内，RP 被**托在本段位下限之上**。

第二层的实现方式值得说明一下：讨论时原本设想的是"RP 照扣、段位显示不变"，但那样做不自洽——RP 已经低于段位下限，`tierOf(rp)` 会算出低段位，显示必然跟着变。要真的做到"显示不掉"，得额外存一个独立于 RP 的段位字段。

最终改成**把 RP 托住**，RP 和段位始终一致。代价是保护期内玩家实际没掉分，相当于"护分"。

## 赛季

```yaml
season:
  enabled: true
  length-days: 60
  soft-reset-base: 2000
  current: 1
```

到期后自动软重置，也可以 `/tdm season reset` 手动触发。重置公式：

```
新 RP = 基准 + (旧 RP − 基准) / 2
```

黄金 II（3250 分）→ `2000 + 625 = 2625`，即白银 II。掉一个大段但保住进度感。

**为什么不清零**：清零会让所有人回到同一起跑线，上赛季的努力完全作废，而且下赛季前期高手和新人会被混在一起，两边体验都差。

赛季到期检查每 5 分钟跑一次——赛季以"天"为单位，查得再勤也只是白白读写一次数据库。

## 存储

两张表，都在 `ranked.db`：

```sql
ranked_players(uuid, name, rp, season, shield_left, played, wins, losses, draws, updated_at)
ranked_meta(key, value)      -- 赛季起始时间、当前赛季编号
```

数据库开了 **WAL 模式**：段位是"主线程读、异步线程写"的模式，默认的 rollback journal 会让两边互相等。

一局结算的十几条更新走**单个事务**——只写进去一半的话会出现"一半人结算了、另一半没结算"，那是最让人困惑的状态。

所有 `RankedStore` 方法都是 `synchronized`：SQLite 单连接不是线程安全的，而读写发生在不同线程。段位操作频率极低，锁不会成为瓶颈。

比赛历史另有两张表，见 [reports.md](reports.md)。
